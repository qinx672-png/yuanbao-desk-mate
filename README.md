# 初中数理成长导师 · 可交互原型

> 每个孩子都能拥有的专属初中数理成长导师
> 学生端 = 数字同学（数字模拟同学形象）｜ 家长端 = AI 家教 ｜ 学科范围：初中数学 + 物理

---

## 一、分享给别人 / 面试官（三种形态，任选）

### 形态 A：单文件 HTML（最省事，推荐做兜底）

```bash
npm install
npm run build:single
```

产物：`dist-single/初中数理成长导师-可交互原型.html`（约 340 KB，单个文件）

- **双击就能打开**，不用装环境、不用联网、不用起服务
- 可以直接微信 / 邮件 / U 盘发给对方
- JS、CSS 全部内联，脚本已降级为普通 `<script>`，规避 `file://` 下的 module 拦截

> 适合：面试现场网络不稳、对方不想点陌生链接、需要留一份可离线归档的交付物。

### 形态 B：在线链接（最专业，推荐做主推）

面试官点开即用，也方便写进简历 / 作品集。

**已配置：GitHub Pages，从 `main` 分支的 `docs/` 目录发布。**

| 项 | 值 |
|---|---|
| 仓库 | `qinx672-png/yuanbao-desk-mate` |
| 线上地址 | `https://qinx672-png.github.io/yuanbao-desk-mate/` |
| 发布来源 | `main` 分支 → `/docs` 目录 |
| 构建方式 | **本地构建后提交产物**（不用 CI，线上跑的就是你本地验过的那份） |

**首次上线**（仓库还没建好时）：

1. 在 GitHub 网页上新建一个**空仓库**，名字 `yuanbao-desk-mate`，**不要**勾选自动生成 README
2. 在本目录执行：

```bash
git remote add origin https://github.com/qinx672-png/yuanbao-desk-mate.git
git push -u origin main
```

3. 到仓库 `Settings → Pages`，Source 选 **Deploy from a branch**，Branch 选 **main**，目录选 **/docs**，保存

**以后每次更新线上版本**（三步）：

```bash
npm run build         # 重新构建 → dist/
cp -r dist/. docs/    # 把产物铺到 docs/
git add -A && git commit -m "更新原型" && git push
```

> - `docs/` 里放的是**构建产物**，里面有一个 `.nojekyll` 空文件——不加上它，GitHub 的 Jekyll 会去处理这些文件，可能出问题
> - `dist/` 与 `dist-single/` 已写进 `.gitignore`，不会被提交
> - `vite.config.ts` 里 `base: './'` 用的是相对路径，所以放在 `/yuanbao-desk-mate/` 这种子目录下也能正常加载

其他平台（当前没在用，仅作备选）：Vercel 导入仓库、Root Directory 填 `prototype`；或把 `dist/` 拖到 netlify.com/drop。

### 形态 C：本地起服务（自己演示时用）

```bash
npm run dev       # http://localhost:5180  改代码即时热更新
npm run serve     # http://localhost:5190  跑构建产物，更接近真实效果
```

`server.host` 已开启，同一 WiFi 下用手机扫码访问局域网 IP，可以真机演示移动端效果。

## 二、建议的走查路线（3 分钟讲清楚）

对方打开后如果不知道看什么，展示效果会大打折扣。建议按这条线走：

**3 分钟主线（走到第 6 步为止就够）**

| 步骤 | 屏 | 一句话话术 |
|---|---|---|
| 1 | 00 角色选择 | 「一个产品两套界面：孩子看到的是同学，家长看到的是家教」 |
| 2 | 01 冷启动画像 | 「第一次见面不问『你数学好不好』——先聊两句，再做一道题看起点」 |
| 3 | 02 学生首页 | 「本子 + 麦克风。**按住麦克风说话，或点一下展开面板点选/打字**——三条路完全等价」 |
| 4 | 04 诊断 | 「AI 在 5-10 秒内做的四件事，我把它显性化了」 |
| 5 | **05 启发式引导辅导** | **核心屏，重点演示**：先探测认知基础 → 教材溯源 → 正向激励 → 思维优先 |
| 6 | 05 走错误分支 | 「答错不打红叉，改成『你是怎么想的』，这是产品价值观落地的地方」 |

**加时项（对方有兴趣再展开）**

| 步骤 | 屏 | 一句话话术 |
|---|---|---|
| 7 | 08 课堂记录 | 「手表端记的课堂内容，回手机上结构化回顾。默认关闭、需老师授权、不存原始音频」 |
| 8 | 12 学习状态趋势 | 「只给行为信号和依据，不下情绪结论——判断权留给家长」 |
| 9 | 13 家长专属 AI 助手 | 「家长能问学情，但**有一条它不给**：孩子和同桌的对话原文」 |

> **第 3 步是全场最容易翻车的地方**：围观的人常常以为要对着麦克风说话才能用，于是站着不敢动。演示时一定先点一下麦克风把面板展开给他看，说一句「说的、点的、写的，对同桌来说是一样的」。

**必须让对方注意到右栏**：每一屏都实时显示该屏对应的**文档条款依据**与**青少年安全设计**。这一栏是在说明「原型不是自由发挥，每个元素都能回溯到文档」，是区分「会画图」和「懂产品」的关键。

中栏手机下方的「演示控制条」不是产品界面，仅供走查：切换夜间护眼、触发休息提醒、切换学生/家长端、重走辅导流程。

## 三、原型内容

- 共 15 屏：角色选择 1 屏 + 学生端 8 屏 + 家长端 6 屏
- 学生端核心形象为**数字模拟同学**（非聊天机器人）：自绘初中生形象，6 种状态（在思考 / 在讲解 / 在鼓励 / 在听你说 / 在指给你看 / 开心）
- 学生首页与冷启动为**本子 + 麦克风**的对话优先形态：本子就是显示区，内容跟着对话逐条浮现，**没有功能货架**（设计参照 Runway Solaris 的「界面世界模型」）
- 辅导主区为「同桌同学 + 共享笔记本」，非聊天气泡
- **说 / 点 / 写三条输入通道完全等价**，都走同一套意图解析。这不是妥协，是因为语音识别（STT）依赖浏览器能力、在国内 Chrome 上常常不可用；更根本的是**语音优先 ≠ 语音唯一**——课堂上、深夜、口齿不清、有口音的孩子都不能被排除在外
- 朗读（TTS）用浏览器内置语音，**不调用任何外部 API Key**（真实产品应由服务端签发短期凭证，前端直接放密钥会泄露）

完整设计说明见上级目录的 `原型说明.md`，产品依据见 `产品定位说明.md`、`核心流程说明.md`、`验证设计.md`。
